# Dict с интересными фишками языка Си

  

Данный проект является тренировочным и не всегда содержит логичные или оптимальные решения.

Побочная задача это создание словаря с ключом `char*` и данными `void*`. Основная это использование в разработке и описание в README интересных вещей, найденных во время чтения книг и статей.

Строится словарь из 4х основных сущностей, состоящих из структур и функций, ими управляющими: `List`, `KeyVal`, `ListKeyVal`, `Dict`.

Каждая из сущностей покрыта тестами и имеет свои фишки реализации. В основе реализации лежит хэш таблица. (возможно вместо листа я буду использовать какое-нибудь дерево, но это пока только планы)

  

# List

Эта сущность является двусвязным списком, каждый элемент которого хранит только ссылки на соседей. Сущность не управляет памятью и только обращается с отдельными `ListNode`.

### Интересное

В основном это довольно банальная сущность. Она намеренно сделана без усложнений, чтобы быть строительным материалом для более крупных структур данных.
В целом хоть сколько-то интересным я считаю позиционные инициализаторы, например, `(List){.size = 0, .head = NULL, .tail = NULL, .error=LIST_OK}`, это довольно наглядный способ создать структуру и при этом все не указанные члены зануляются.

# KeyVal

Это тоже строительный материал для более сложных структур, но тут я уже использовал более запутанные вещи в реализации. В целом это пара значений из ключа и значения, которые могут быть заданы извне.

### Интересное

Первое, с чем предстоит столкнуться читателю этой части кода, это функция, а точнее макрос создания объекта `keyval_create(name, ...)`. 
Сам объект содержит в себе две ссылки `void*` для хранения любых ключей и значений, а ещё поля типа `TypeFuncs`, каждый из которых должен хранить функции обращения с ключом и значением. 
По умолчанию в макросе содержится создание объекта хранящего две строки, однако, следуя структуре, возможно определить любые пользовательские типы, например, для тестов был определён тип массива чисел. Ещё в макросе содержится занятная особенность использования позиционных инициализаторов: при заполнении структуры всегда будет выбрано последнее указанное значение, получается, что предыдущий затерается. Этот механизм позволяет задавать значения по умолчанию, хотя компилятор `gcc` требует специального флага `--ms-extensions` для того, чтобы не считать это подозрительным.

Второе, что я считаю стоящим внимание, является сам `TypeFuncs`, который хранит в себе функции взаимодействия с типом внутри `KeyVal`. Подобное размещение и единообразие позволили определить единый путь выполнения функций над `KeyVal` и получить довольно лаконичный вид `kv->val_funcs.free(kv->value);`, например.

В итоге можно сформулировать интерес этого типа так: чтобы безопасно хранить любые данные в `void*`, мы должны озаботиться, как трактовать их. В этом конкретном случае: мы храним функции, предназначенные для интерпретации данных, рядом с оными, сообщаем, если функция для интерпретации не предоставлена и по умолчанию даём самый распространённый случай парных данных, как `{ char* : char* }`.
